# Evaluation contract

Adopted for A01 on 11 October 2026. **No benchmark or audio experiment has been run.** A04 implements these checks; A05 compares matchers; A06 checks the baseline workflow; D02 runs integrated evaluation before D04 listening. The [record contract](RECORDS.md) defines source identity and time coordinates.

## Separate questions and evidence

| Check | Protocol and observable output | Supported claim and limit |
| --- | --- | --- |
| Published human timbre judgments | Record dataset/version, permitted use, sound/rating coverage, and excluded items. Compare model distances with human dissimilarity ratings using rank correlation, with tie handling and uncertainty resampled by independent sound/source group. Report each dataset separately. | Perceptual ranking agreement within that evaluated data. Does not establish relevance to Loulou or recall across arbitrary songs. |
| Same source, different phrases/nearby pitches | Generate reproducible renders from a fixed instrument/preset with varied phrases and a declared nearby-pitch range; retain seeds and render settings. Report query-to-known-source rank, retrieval at predeclared shortlist sizes, and performance by pitch/phrase condition. | Controlled source consistency under those changes. Same-preset identity is a proxy, not proof of identical perceived timbre; transformations may change character. |
| Contrasting sounds, same notes | Hold note sequence, pitch, level policy, and duration policy fixed while changing deliberately chosen source/preset or acoustic properties. Report pairwise ordering and score margins against same-source controls, separately from human-rated metrics. | Whether note similarity overwhelms controlled sound-character differences. Different preset IDs alone are not independent perceptual labels. |
| Known targets inside mixtures | Insert known target events at recorded sample positions with varied accompaniment and target levels; include absent-target mixtures and acoustically similar distractors. Report candidate hit rate at predeclared K, temporal overlap/boundary errors, and final refined results separately. Report score/rank distributions on absent-target cases. | Candidate coverage, localisation, and distractor behavior for these controlled mixtures. No claim of arbitrary-song recall. A forced top-K list cannot establish that a target is present; any rejection rule must be fitted on development data and frozen before held-out checks. |
| Indexing, mapping, original playback | Use fixtures with known file hashes, events, crop offsets, excerpt status, resampling, and missing/stale assets. Compare retrieved identities, mapped sample intervals, and original playback ranges with fixture truth. | Technical correctness, independent of whether the sound is relevant. Reference-copy retrieval is a useful diagnostic only. |
| Later listening on real recordings | At D04, present about ten diverse distinct-song candidates with original passages and timestamps; retain optional similar/dissimilar/uncertain judgments and query/run versions. Record how candidates were sampled. Report judged relevance and uncertainty, including weak or fewer results honestly. | Relevance of judged candidates to Leonardo's intended sound. Top-result judgments alone cannot measure missed matches or catalogue-wide recall. No new user labels are needed before this stage. |

Keep three data roles explicit in manifests: **real-recording discovery catalogue**, **generated engineering diagnostics**, and **published human-rated evaluation data**. Do not silently mix generated tracks into discovery results or count diagnostic copies of the query as discoveries. Mark unavailable evidence as unavailable, not as a pass or a request for Leonardo to create labels.

Measure candidate retrieval before refinement. Report the shortlist, its size, and target coverage independently of the reranked list: a reranker cannot recover a passage it never receives. Compare original-audio processing with any separation variant on the same examples, reporting both retrieval differences and resource cost. Playback always returns to the original available mixture.

## Technical acceptance requirements

These are correctness requirements, not timbre-quality percentages. A claimed complete search run must satisfy all applicable invariants on the implemented fixture suite; missing checks remain untested.

| Requirement | Observable acceptance evidence |
| --- | --- |
| Input identity and provenance | Every analysed asset resolves to its source ID and byte hash; acquisition/permitted-use status is explicit. Missing/changed files produce a visible invalidation or error, not reused results attributed to different audio. |
| Safe bounds and unknowns | Verified intervals are finite, ordered, and within decoded file bounds. Unknown paths/hashes/offsets remain null with reasons; unverified requests never become verified crops automatically. |
| Time mapping | Full-track crops, known-offset excerpts, unknown-offset excerpts, and composed processing maps resolve to the correct source coordinates. Unknown-offset excerpts stay excerpt-relative. Lossless sample-index mapping matches fixture boundaries exactly apart from declared sample rounding; seconds round-trip within one decoded source sample. |
| Decoder/playback behavior | Original source hash and interval match the returned result; both query and result can play. Compressed seek or tool latency tolerance must be based on measured decoder/processing behavior and fixed before evaluation, with residual error reported. Do not silently use a broad arbitrary tolerance. |
| Index and cache validity | Cache/index keys include source hash, preprocessing/config version, and representation/checkpoint version. Changing any dependency invalidates affected entries; missing assets cannot silently resolve to another file. |
| Reproducibility | Retain source/feature versions, split IDs, seeds, configuration, code revision, environment, and hardware. Identical inputs in the declared environment reproduce rankings with a stable tie rule; any numerical tolerance is specified before the comparison. |
| Discovery identity | Exact copies, re-encodings, and known near-duplicates of the query recording are identified and excluded from discovery counts. Unknown duplicate coverage is disclosed. Aggregation does not present many overlapping windows as distinct-song successes. |
| Score interpretation | Each score states metric, direction, normalization, and stage. Timbre and pitch contributions are inspectable. No uncalibrated score is presented as a probability or as independent proof of quality. |
| Honest failure | Empty catalogues, unavailable models, absent/missing inputs, out-of-bounds requests, and stale indexes produce explicit outcomes; no fabricated playable results or benchmark passes. |

A01 only reviews the contract and manifest structure. It does not implement or claim success on these future technical checks.

## Model selection and leakage control

1. **Freeze the protocol before comparison.** In `manifests/evaluation/`, record dataset versions/hashes, eligible examples, source/preset family IDs, split assignment and seed, metrics/direction, K values, pitch/mixture conditions, ranking/tie rules, resource budget, and the selection rule. A02 supplies resource limits; A04 supplies fixtures and a dated protocol before A05 scores are inspected.
2. **Keep related examples together.** Group crops, re-encodings, transformations, stems, and known alternate copies by recording family. Group generated examples by instrument/preset identity, not random individual render. For mixtures, prevent shared target families and related accompaniment recordings from crossing development and held-out groups. Document the actual scope of any instrument-versus-preset split.
3. **Split human-rated data by sound/source family.** Retain evaluation comparisons whose endpoints satisfy the chosen split policy; disclose cross-split pairs removed and any resulting coverage loss. Do not leak a transformed sound through a different pair. Prefer official independent splits when suitable, and record their limitations.
4. **Use development data for choices.** Compare a small justified shortlist containing an acoustic baseline and available pretrained alternatives. Choose preprocessing, aggregation, optional separation, pitch weighting, and model settings on development data under the frozen rule. Keep technical correctness, perceptual agreement, generated-source consistency, and cost separate in the report.
5. **Reserve held-out evaluation.** Run final held-out checks after choices are frozen. Do not repeatedly tune against them or pick the winning model on the final set. If a failed final check leads to tuning, disclose that it is now development evidence and reserve new independent evaluation data for the next final claim.
6. **Record remaining leakage.** Unknown overlap with pretrained-model training data remains unknown, not "clean" by assumption. Record dataset/source overlap, duplicate-detection coverage, excluded examples, and changes to the protocol.

No numerical perceptual-quality target is adopted in A01: no selected dataset, user-independent baseline, or measured variance supports one yet. Any later quality threshold needs a written basis (published comparable evidence, a pre-existing external reference, or development-only evidence), its metric/population, uncertainty rule, date, and rationale **before examining the comparison it governs**. If the basis is insufficient, report descriptive results rather than inventing a universal timbre-accuracy percentage. Technical tolerances derive from file/decoder precision; K and run limits derive from the intended interface and resource budget, not observed success.

The matcher's own similarity scores are not an independent evaluation label. Generated-source truth establishes identity/location, human-rated datasets establish perceptual agreement within their domain, and D04 judgments establish relevance of listened-to real candidates. Report those three claims separately. Measuring general catalogue recall would require an independently assessed candidate population beyond the returned top results; that evidence is not supplied by A01.

## Future evidence report

Each report should identify its stage/run, code and environment versions, input and split manifests, frozen protocol, methods and resource use, per-check denominators/coverage/uncertainty, failures and unavailable checks, and the limits of its conclusions. Include candidate-before-refinement measurements and any separation ablation. Mark a substitute reference clearly. No report may describe an unrun check as successful.
