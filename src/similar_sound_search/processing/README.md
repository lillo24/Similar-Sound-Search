# Incremental processing owner

`contracts.py` defines exact native row identity, explicit input schemas and the
classified consumer guard. `context.py` owns fixed roots, counted metadata and the
single cumulative pool. `cache.py` resolves compact validated array memberships
independently of bundle packing, retaining producer and native-row evidence.
`api.py` owns metadata-only planning, the deterministic graph, status/cancel/result
and bounded inventory APIs. `job.py` owns claims, attempts, reservation/settlement
journals, crash reconciliation and final publication under OS locks.
`engine.py` adapts native feature/query/scoring units to the existing frozen encoder,
grid, cosine and complete-population C02 fusion. `historical.py` audits C01 banks and
the exact B03/C02/C03/playback chain without calling closed workers or writing there.
`commands.py` routes CLI/foreground playback and bounded admin workers.
`validation.py` supplies independent scalar/native answers and generated fixtures.
DSP and ranking contracts retain their earlier owners. The separate
[`application/` owner](../application/README.md) implements D01 without modifying
this historical processing source or its partial request/pool.

`runner.py` owns a single actual Windows worker process with preserved virtualenv
paths/prefix and a hard deadline, avoiding the extra venv launcher PID.

`records.py` losslessly interns repeated native-row reference fields. The public
membership reader supports both earlier full records and the compact format.
