# Candidate refinement

`context.py` owns one C03 allowance/publication boundary and a separate read-only
C02 view. `importing.py` validates historical membership and native row semantics.
`geometry.py` owns the pure fixed grid, objectives, ties and lineage roles.
`engine.py` publishes compact original-mixture local features and atomic group
results, with unchanged reuse and a C04 dependency export. `development.py` adapts
the separate saved C02 development schema and evaluates one fixed batch.
`validation.py` supplies independent scalar/native geometry answers.
`commands.py` routes the CLI and preflight; `job.py` enforces offline bounded
workers and lifetime accounting. `report.py` publishes original scored/context
playback and native verification. No historical worker or allowance is reopened.

`report.py` also owns the explicitly declared renderer-only repair: preserve the
first bundle/proofs, charge byte-identical media copies and verify a new report
under its separately audited consumer. Numerical execution and reuse stay closed.
