# Installed local distribution

This package owns D03 packaging, readiness and the one finite post-delivery
runtime allocation. Numerical algorithms remain in `similar_sound_search`.

- `bootstrap.py` is the stdlib-only archive verifier/offline installer copied to
  each code archive as `setup.py`. It rejects undeclared members, changed hashes,
  traversal, junctions and duplicate paths before installation.
- `cli.py` and `__main__.py` own explicit prepare, doctor, foreground start,
  same-host relocation and verification sealing. `__init__.py` owns the independent
  release ID; core 0.3.0 remains the frozen numerical version.
- `assets.py` follows selected real-catalogue/three-result dependencies into a
  separately verified private workspace. `files.py` owns strict paths and hashes.
- `authority.py` binds one workspace UUID to one external LocalAppData registry.
  `context.py` owns fixed share counters, protected transactions and immutable
  closed-allocation receipts. Every pool publication advances its external
  generation/checkpoint. Failed publication is an explicit recovery error.
- `policy.py` owns fixed shares and complete-path estimates. Metadata is reserved
  inside managed output; normal use remains unspent during delivery QA.
- `runtime.py` connects the existing application coordinator, query library,
  adoption, scoring, aggregation and original media to this owner. `worker.py`
  is the installed actual-PID worker entry. Shared query metadata/features can be
  reopened from either share, while all new writes debit the active share.
- `contracts.py` requires exact core/adapter/UI maps and the inherited numerical
  hash. `doctor.py` checks platform/pins/private records/model and reports distinct
  capabilities and complete-search remaining capacity.
- `resources/THIRD_PARTY_NOTICES.txt` identifies vendored/dependency notices and
  separate private prerequisites.

Each share permits 3,600 seconds, 256 workers, 90,000 source-read seconds, 512 new
query rows, 6,000 processed seconds, 32 MiB features, 64 jobs, 64 clips/128 MiB,
256 MiB metadata (32 MiB protected), 64 MiB preparation, 128 MiB imports and
512 MiB managed output. Search bounds additionally cap 1,200 aggregate worker
seconds, 128 workers, 30,000 source-read seconds and 96 MiB ordinary metadata.
Each actual PID has a 120-second timeout, one numerical thread and a 1 GiB
checked numerical working estimate; RSS is measured, without OS RSS enforcement.

There is no reset/refill command. Restore the latest whole workspace and external
registry after filesystem failure; stale checkpoints fail. Stop the server before
the explicit relocation command, which renames the same workspace and updates
only the external canonical path. If interrupted between rename and registry
publication, restore the old path before retrying. Keep original backups private.
Retain/export completed results by default; user deletion and future explicit
policy amendments are separate work. Never create an alternate registry to renew
this authorization. Optional C03/D02 history views are omitted from this product;
the original checkout retains their evidence unchanged.
