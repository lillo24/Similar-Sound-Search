## 1. Define a durable query contract

Add a clear query-management owner and source map. Inspect `search/query.py`, `search/pitch.py`, `search/ranking.py`, `events/selection.py`, `events/compatibility.py` and `separation/artifacts.py`/`context.py` first. Reuse their validated boundaries instead of copying the pipeline. Document any necessary shared-interface change as a distinct integration step.

Separate three things: a named query with immutable revisions, the audio/features materialized from a revision, and a search execution against a particular index/pitch policy. A display name is not a content identity; a saved feature path alone is not a reusable query recipe. Each execution must bind the exact revision and artifacts it used, including when a mutable name later points elsewhere.

| Contract part | Required content and behavior |
| --- | --- |
| Source and coordinates | Original byte/PCM identities, technical metadata, available-file versus master/excerpt coordinates, verified or unknown version/offset, parent records and provenance. Local paths are explicit bindings, not identities. |
| Selected examples | Integer half-open native-frame bounds and source rate; selection origin/version; event/context distinction; overlap, censoring and uncertainty. Preserve event evolution; loading a query must not redetect or recrop it automatically. |
| Processing variant | Original by default; explicit optional method/configuration/version, component, transformation/output hashes and mapping. Retain original context alongside the processed event. A new waveform remains a B02-style transformation, never a fictitious unchanged A02 crop. |
| Conditioning cue | Separate from retrieval examples: source/bounds/hash, availability, provenance and known contamination. Only explicitly selected retrieval examples contribute to the query feature set. Guided processing requires its actual cue; an ordinary query does not. |
| Representation and artifacts | Frozen matcher/preprocessing identity, selected PCM identities, validated feature bindings and materialization status. Distinguish a valid recipe from ready, missing, corrupt, incompatible or interrupted artifacts. |
| Search preference | Pitch off by default, explicit version/weight/scale and estimate provenance; timbre aggregation and ancestry exclusions remain visible. Index/result bindings belong to the execution, not the display name. |

Retain supported limits: one to eight examples, at most thirty seconds per original example, and the stricter B02 processing/cue limits where applicable. B03 cannot make a twelve-second processing context feasible merely by changing its label; respect the actual channel/rate allocation checks. Missing media or a cue must produce actionable availability errors. A cached feature cannot hide a missing required original or stale transformation.

Provide CLI operations to save/create a revision, list/show it, rename its display label, select a specific revision, validate/materialize and search it. Changed bounds, cue, processing choice or semantic preference create an explicit revision/execution identity; never overwrite historical results. Reopening an earlier revision must reproduce its choices. Do not silently switch a missing experimental variant to original; offer original as a distinct explicit choice.

Support a small JSON recipe export/import with explicit local asset binding. Export a dependency inventory and hashes without machine-specific absolute paths, secrets or audio. Test relocation through explicit hash-checked bindings, including same filename/different bytes and wrong parent/map. Do not crawl disks for substitutes, infer identity from names, or rewrite an old receipt to disguise relocated assets. ## 3. Keep approximate pitch secondary and explicit

Reuse the existing conservative classical estimator initially. It accepts stable narrow monophonic fundamentals roughly within 50..500 Hz and abstains on many mixed, unstable or out-of-range signals. Those are implementation limits, not evidence of general polyphonic pitch tracking. No new pitch model is needed. Retain abstention/reason information and bind estimates to the exact audio support, channel/preprocessing policy and estimator version.

Use an explicit bounded penalty added to the unchanged timbre distance; show both components and the resulting rank. Keep weight **0 by default and no greater than 0.05**. Define absolute semitone/register mismatch, clipping, scale and aggregation; do not silently fold octaves into pitch classes. The legacy twelve-semitone scale is an existing setting, not a proven useful tolerance. Freeze one nonzero policy before comparison; at most one additional predeclared sensitivity setting is allowed. Any different scale belongs to a new B03 policy, not an edit to `config/search.json` or historical results. Do not choose a setting after inspecting catalogue ranks.

Start from the documented mean per-example mismatch and all-required-query-estimates-reliable gate. Show per-example estimates and the limitation when a query contains different notes; do not infer an intended melody or choose the most convenient note. Missing/ambiguous pitch contributes zero, with a visible reason, rather than an invented frequency or a penalty for uncertainty. If every estimate abstains, ordering must equal pitch-off. A nonzero preference is not a calibrated probability or presence detector.

Preserve A06 semantics: **timbre selects one best passage per original duplicate group; optional pitch only reorders those group winners**. Do not let pitch select a different window, enlarge the candidate pool, alter timbre embeddings or analyze all 44,025 overlapping windows. If reusing winners for a pitch toggle, retain and validate the complete eligible winner set before taking top ten; reranking only a previous top ten is not equivalent. Bind that intermediate to query, index/shards, exclusions and ranking policy. Otherwise use one bounded fresh rank and disclose its cost. No global pitch index is required.

Pitch measured on a processed variant describes that waveform. It is not automatically the original intended layer's pitch. Keep cue-only pitch out of the query unless the contract explicitly selects it. Original audio and pitch-off remain defaults after B03; controlled diagnostics cannot establish a human preference for changing them.
