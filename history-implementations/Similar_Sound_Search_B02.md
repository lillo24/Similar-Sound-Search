## 1. Define a small, honest processing comparison

Provide an explicit processing interface with input region, optional audio cue, method/version/configuration, output components and a no-processing mode. The no-processing route must preserve the native selected samples and remain usable when optional processing is unavailable or harmful. Selection is fixed before retrieval; do not retune B01's detector during this experiment.

Use three roles, with at most one configured approach per processed role after a bounded feasibility pilot:

| Role | Required behavior and interpretation |
| --- | --- |
| Original mixture | Same source region, event bounds and matcher as the processed arms. This is the primary baseline, including when it wins. |
| Broad separation | One feasible pretrained broad-stem separator, or a lightweight harmonic/percussive decomposition using the installed numerical stack. Name the actual outputs: harmonic/percussive components are not isolated instruments; a model's vocals/drums/bass/other categories do not identify an arbitrary synthesizer or intended layer. |
| Cue-guided extraction | A bounded method genuinely conditioned on an explicit audio example/selected event. A small reference-template mask or constrained factorization is an acceptable experimental baseline. Record the cue and its limitations. Cropping, generic filtering or selecting a named broad stem alone does not establish targeted extraction. |

Inspect official code, model terms, checkpoint size and dependency/runtime requirements before acquiring anything. Admit at most **one new pretrained separator configuration/checkpoint**; do not explore a model zoo. [Demucs's official documentation](https://github.com/facebookresearch/demucs) is one starting point, not a mandated dependency or evidence it fits this machine. Its original repository is archived. The documented two-stem output still computes the complete separation; it is not a memory shortcut. Its CLI can rescale stems independently, so a wrapper must preserve or explicitly account for gains. Pin the chosen revision/checkpoint and test the actual Windows CPU path within the existing ceilings.

If that candidate cannot meet terms, dependency, memory, transfer or worker limits, record the concrete reason and implement/exercise the lightweight broad-component fallback. For the cue-guided role, deliver a bounded numerical method or an already available suitable model instead of stopping at a large model's incompatibility. State the equations, finite iteration/template counts, initialization/seed, STFT/mask/reconstruction settings and failure policy actually implemented. Per-clip numerical fitting is permitted; general-model training and fine-tuning are not.

Use cue audio rather than an invented instrument name. A language-conditioned system such as [AudioSep](https://github.com/Audio-AGI/AudioSep) has a different input contract; it cannot infer Leonardo's intended sound from an unverified description. In real mixed audio the cue may itself be contaminated. Label that uncertainty, and keep the original route available. If a processed role cannot run, report it as unavailable/partial; do not count an identity output or saved placeholder as successful extraction.

Keep component choice independent of candidate results and hidden evaluation truth. A fixed cue-based routing rule is permissible if declared before scoring. A best-ground-truth-stem choice is oracle-only. If the method searches several components, disclose that extra search opportunity, apply a fixed recording-level aggregation and compare a control with the same candidate support. Do not report whichever stem happens to retrieve best as a deployable selection rule.

## Primary research starting points

Checked at authoring; re-check exact versions and artifact terms before implementation. These describe methods, not results on this project's recordings.

- [Demucs official implementation](https://github.com/facebookresearch/demucs): broad music stems, runtime/options and gain behavior; the archived repository points to its author's fork.
- [Harmonic/percussive separation research and comparison methods](https://www.audiolabs-erlangen.de/resources/MIR/2018-ICASSP-HPSS_KAM_NMF/): includes the original median-filtering reference and examples of cross-talk/artifacts.
- [FMP: constrained NMF spectrogram factorization](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C8/C8S3_NMFSpecFac.html): template/activation constraints and limitations. Its score-informed examples are not a licence to feed evaluation notes to an operational audio-cue extractor.
- [AudioSep official implementation](https://github.com/Audio-AGI/AudioSep): language-conditioned separation, with a different conditioning contract from this project's selected audio example.
